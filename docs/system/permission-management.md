# 权限管理与展示规范

角色管理保留列表、角色编辑和权限树；矩阵只读对照配置，溯源星图展示配置关系并进入原有编辑流程。三种视图共享权限目录，不能各自维护分类词表或另存一套授权数据。

## 权限标识与资源分组

- 系统与平台权限使用 `{domain}:{resource}:{action}`，子资源可使用 `{domain}:{subdomain}:{resource}:{action}`。例如 `system:user:view`、`system:security:api-key:revoke`、`platform:agent:tool:edit`。
- 插件权限使用 `plugin:{pluginCode}:{action}`，pluginCode 必须是插件稳定 code；显示名称可以改，不能用名称充当授权标识。
- 资源和动作使用小写字母、数字及连接词的短横线。一个权限码表达一个资源动作，禁止把多个资源混在同一码内。
- 权限树的层级固定为 **业务域 → 资源 → 动作分类 → 权限**。资源 key 是去掉末段动作后的完整码，不能以中文 module/name 为 key，以免同名模块合并或名称变更丢失选中状态。
- 业务域默认依次为系统管理（system）、平台能力（platform）、插件（plugin）、移动端（mobile）、其他来源。归属服从现有 system/platform 边界，不因页面样式调整而移动能力归属。
- 资源中文名集中维护在宿主 `src/utils/permission-catalog.ts`。已知资源使用明确业务名称；新插件/未知资源可回落有意义的中文 module，仍以稳定资源码区分。宽泛的“系统管理”“平台能力”不得代替资源名称。
- `@PermissionRegister.module` 使用中文业务模块名。新增同资源权限的 module 保持一致，权限 name 使用清楚的动作与对象，desc 描述具体端点用途。同一码被多个端点使用时，不应依靠注册扫描顺序决定它的业务含义。

## 动作分类

| 分类 | 动作词 | 含义 |
| --- | --- | --- |
| 查看 | view、export、download | 读取、导出、下载 |
| 操作 | create、edit、import、upload、use、generate、publish、connect、send、test、run、invoke、execute、enable、disable、assign-*、dataset、report、accept | 写入与执行业务动作 |
| 管理 | manage、config | 资源管理与配置 |
| 危险 | delete、kickout、revoke、impersonate | 删除、踢出、撤销、身份代入 |
| 其他 | 历史或未规范动作 | 显式兼容，不能伪装成规范权限 |

`assign-*` 匹配非空的规范动作后缀，例如 assign-role、assign-dept、assign-team；不能只硬编码已有的两个动作。列表、权限树、矩阵、星图共用 `permissionCategoryMeta`、`permissionCategoryOf` 和 `permissionResourceOf`。

分类是展示与评审规则，不能从“查看”“危险”标签推导授予或撤销权限。资源仍须独立注册 view、写入、delete 等权限，并由后端执行检查。不能用一个 manage 权限包住所有操作后仅在前端隐藏按钮。

已有 `query`、`internal` 等非词表动作继续进入“其他”。整理展示时禁止直接重命名数据库中的权限码；确需迁移时必须单独设计旧码兼容、角色授权迁移、端点检查、菜单种子、插件契约和回滚。新增动作词应同一提交更新 AGENTS.md、架构 skill、knowledge.json 与集中分类词表。

## 权限树的兼容行为

- 只显示 ACTIVE 的登记权限。未知或暂失效的插件权限码保留在角色配置内，插件恢复后按既有判权规则重新生效。
- 搜索只改变展示；勾选回传时只更新当前可见叶子，保留被过滤的选择和未知码。业务域/资源/分类节点不是权限，不得把这些虚拟 key 保存进角色。
- “全选”合并所有 ACTIVE 目录码并保留未知码；“清空”是明确清除整个角色授权的操作。新视图不得自行重建可见码集合并全量覆盖原授权。
- 角色列表显示现存 ACTIVE 权限数；矩阵仍保留停用角色的配置，并标注“配置未生效”。

## 配置关系与实际判权

用户分配多个角色表示存在多个身份。实际权限按当前所选部门解析当前角色，只有用户启用、邮箱已验证且角色启用时才生效。权限不能按所有已分配角色的并集解释。只有 `SystemRoleType.SUPER_ADMIN` 获得 `*` 通配权限，角色 level 或名称不能替代此判断。

会话上下文存放在当前 tokenSession，不能将操作者的 tokenSession 套到其他用户。全景中的本人使用本次会话上下文（contextSource=SESSION）；其他用户显示其默认部门/角色上下文（contextSource=DEFAULT），明确实际登录会话可以切换。

菜单关系由与真实动态菜单相同的可见码计算产生，须包含 BUTTON 权限上溯页面、结构祖先承载、插件运行状态及平台能力状态。类别/布局祖先不是独立业务操作，不计为未授权菜单。停用或不可用的菜单不计为待诊断的未授权菜单。

## 全景接口与统计口径

`GET /api/system/roles/permission-overview` 由 `system:role:view` 控制。角色与权限目录可用于只读矩阵；用户关系、成员统计额外要求 `system:user:view`，菜单关系与菜单统计额外要求 `system:menu:view`。无相应权限时数据为空、统计为 null，页面显示未授权，不能伪显示为 0。

用户查询分页，上限 100，默认每页 30，支持 userKeyword、userRoleId、userUnassignedOnly。查询只投影用户名/昵称、状态、验证状态、部门与角色 ID，不能读取或下发邮箱、手机、密码、自定义字段。所有 Long/Snowflake ID 在 JSON 与 TypeScript 中保持 string。

- 用户总数：全量配置用户数，包含停用用户。
- 闲置角色：没有任何用户配置关联的角色；停用用户的关联仍算占用，不能根据当前页用户推导。
- 无角色用户：未配置任何角色 ID 的用户。
- 授权关系数：全量用户与去重后的配置角色 ID 关联数。
- 未授权菜单：启用且运行可用的 MENU/LINK/BUTTON，在所有活动角色身份下均不可见的节点；不包含结构祖先、不可用插件或停用能力的菜单。

统计在仓储端聚合全量数据；用户分页/搜索结果只影响当前展开的用户节点。星图须标注用户分页与卫星展示上限，隐藏节点不代表无权限，配置关系线不代表用户此刻正在使用该角色。

## 编辑与验证

角色节点或矩阵角色标题进入原有角色编辑/权限树，须有 system:role:edit。用户节点进入原用户编辑，菜单节点进入原菜单编辑，分别须同时具备资源 view 与 edit。类别主环用于展开，权限节点用于反查相关角色，权限码没有新的独立写入入口。

保存、启停、导入或从用户/菜单编辑返回后刷新全景。异步查询须防止过期响应覆盖新选择，查询失败必须可重试。星图使用页面级 SVG 表达截图的球体、刻度环和轨道，新增按钮/输入/详情复用既有 Yd 入口；不修改共享图谱组件，不增加外部图数据库依赖。

变更至少验证：权限树搜索下保留隐藏/未知选择、assign-* 分类、仅 SUPER_ADMIN 系统类型通配、停用角色的配置语义、用户/菜单读取隔离、全量统计不受分页影响、他人会话隔离、真实菜单可见规则。执行受影响后端定向测试、前端测试 typecheck、完整 Vue typecheck/构建及定向 lint。
