# 权限管理与展示规范

角色管理保留列表、角色编辑和权限树；矩阵默认只读，可明确切换为授权编辑；溯源星图展示真实配置关系，提供权限细则、单项授权/撤销及用户角色分配，同时保留原有编辑入口。三种视图共享权限目录与原角色、用户数据，不能另存一套授权关系。

## 权限标识与资源分组

- 系统与平台权限使用 `{domain}:{resource}:{action}`，子资源可使用 `{domain}:{subdomain}:{resource}:{action}`。例如 `system:user:view`、`system:security:api-key:revoke`、`platform:agent:tool:edit`。
- 插件权限使用 `plugin:{pluginCode}:{action}`，pluginCode 必须是插件稳定 code；显示名称可以改，不能用名称充当授权标识。
- 资源和动作使用小写字母、数字及连接词的短横线。一个权限码表达一个资源动作，禁止把多个资源混在同一码内。
- 权限树的层级固定为 **业务域 → 资源 → 动作分类 → 权限**。规范动作码以去掉末段动作后的完整码作为资源 key；历史页面入口码若本身就是已知资源码，则与该资源的接口动作归入同组，仍保留独立授权叶子。插件始终以 `plugin:{pluginCode}` 为资源 key，历史嵌套码标注兼容。不能以中文 module/name 为 key，以免同名模块合并或名称变更丢失选中状态。
- 已有日志/监控/主题菜单的入口码与实际按钮归属不同，集中 `resourceAliases` 按 `SystemMenuModule` 的真实绑定归一：`system:api-log`、`system:login-log`、`system:agent-trace`、`system:online-user`、`system:redis-monitor`、`system:resource-monitor` 分别归入对应 `system:monitor:*` 资源，`system:theme` 归入 `system:setting:theme`。这是资源展示映射，不能用中文同名猜测归属，也不改变任何权限叶码。
- 业务域默认依次为系统管理（system）、平台能力（platform）、插件（plugin）、移动端（mobile）、其他来源。归属服从现有 system/platform 边界，不因页面样式调整而移动能力归属。
- 资源中文名集中维护在宿主 `src/utils/permission-catalog.ts`。已知资源使用明确业务名称；新插件/未知资源可回落有意义的中文 module，仍以稳定资源码区分。宽泛的“系统管理”“平台能力”不得代替资源名称。
- 资源标签从完整目录统一计算：可用声明优先，其次为直接 owner/资源入口声明，再按短名和字典序稳定选择。同业务域不同资源仍同名时附资源码消歧；筛选不能改变同资源标签。
- `@PermissionRegister.module` 使用中文业务模块名。新增同资源权限的 module 保持一致，权限 name 使用清楚的动作与对象，desc 描述具体端点用途。同一码被多个端点使用时，不应依靠注册扫描顺序决定它的业务含义。

## 动作分类

| 分类 | 动作词 | 含义 |
| --- | --- | --- |
| 查看 | view、export、download | 读取、导出、下载 |
| 操作 | create、edit、import、upload、use、generate、publish、connect、send、test、run、invoke、execute、enable、disable、assign-*、dataset、report、accept | 写入与执行业务动作 |
| 管理 | manage、config | 资源管理与配置 |
| 危险 | delete、kickout、revoke、impersonate | 删除、踢出、撤销、身份代入 |
| 其他 | 历史或未规范动作 | 显式兼容，不能伪装成规范权限 |

`assign-*` 匹配非空的规范动作后缀，例如 assign-role、assign-dept、assign-team；不能只硬编码已有的两个动作。列表、权限树、矩阵、星图共用 `permissionCategoryMeta`、`permissionCategoryOf` 和 `permissionResourceOf`。

分类是展示与评审规则，不能从“查看”“危险”标签推导授予或撤销权限。资源仍须独立注册 view、写入、delete 等权限，并由后端执行检查。不能用一个 manage 权限包住所有操作后仅在前端隐藏按钮。

已有 `query`、`internal` 等非词表动作继续进入“其他”。整理展示时禁止直接重命名数据库中的权限码；确需迁移时必须单独设计旧码兼容、角色授权迁移、端点检查、菜单种子、插件契约和回滚。新增动作词应同一提交更新 AGENTS.md、架构 skill、knowledge.json 与集中分类词表。

## 权限树的兼容行为

- 只显示 ACTIVE 的登记权限。未知或暂失效的插件权限码保留在角色配置内，插件恢复后按既有判权规则重新生效。
- 搜索只改变展示；勾选回传时只更新当前可见叶子，保留被过滤的选择和未知码。业务域/资源/分类节点不是权限，不得把这些虚拟 key 保存进角色。
- “全选”合并所有 ACTIVE 目录码并保留未知码；“清空”是明确清除整个角色授权的操作。新视图不得自行重建可见码集合并全量覆盖原授权。
- 角色列表显示现存 ACTIVE 权限数；矩阵仍保留停用角色的配置，并标注“配置未生效”。
- 权限分配弹窗按过滤后的权限叶子分页，默认 100 项，可选 50/100/200；只把当前页的叶子和祖先路径交给公开 `YdTree`，再叠加固定高度虚拟窗口。默认只展开业务域，展开全部和搜索仍保持虚拟渲染。目录与检索索引只在权限目录变化时构建，勾选不重建全树；搜索防抖 180ms，覆盖完整目录，复用叶节点，清除搜索恢复原展开状态，筛选或页大小变化重置页码。
- 分组勾选与“勾选本页/取消本页”只修改当前页可见叶子；“全选全部/清空全部”明确表示完整目录/完整配置范围。跨页、搜索隐藏、未知插件权限和历史通配在页面状态内保留，不能根据本页数据重新覆盖授权。分组的完整勾选状态只从本页叶子推导，虚拟分组 key 永不进入表单。目录数据以浅响应式替换，不为每个登记字段建立深层监听。

## 配置关系与实际判权

用户分配多个角色表示存在多个身份。实际权限按当前所选部门解析当前角色，只有用户启用、邮箱已验证且角色启用时才生效。权限不能按所有已分配角色的并集解释。`SystemRoleType.SUPER_ADMIN` 自动获得 `*` 通配权限，角色 level 或名称不能替代此判断；历史普通角色若原配置含 `*`，也会被既有判权机制解释为通配。矩阵和快捷操作锁定这些角色的单项授权，明确提示使用原权限树处理通配配置，不能暗示逐项撤销可限制通配。

会话上下文存放在当前 tokenSession，不能将操作者的 tokenSession 套到其他用户。全景中的本人使用本次会话上下文（contextSource=SESSION）；其他用户显示其默认部门/角色上下文（contextSource=DEFAULT），明确实际登录会话可以切换。

菜单关系由与真实动态菜单相同的可见码计算产生，须包含 BUTTON 权限上溯页面、结构祖先承载、插件运行状态及平台能力状态。类别/布局祖先不是独立业务操作，不计为未授权菜单。停用或不可用的菜单不计为待诊断的未授权菜单。

## 全景接口与统计口径

`GET /api/system/roles/permission-overview` 由 `system:role:view` 控制。角色与权限目录可用于只读矩阵；用户关系、成员统计额外要求 `system:user:view`，菜单关系与菜单统计额外要求 `system:menu:view`。无相应权限时数据为空、统计为 null，页面显示未授权，不能伪显示为 0。

用户查询分页，上限 100，默认每页 30，支持 userKeyword、userRoleId、userUnassignedOnly。查询只投影用户名/昵称、状态、验证状态、部门与角色 ID，不能读取或下发邮箱、手机、密码、自定义字段。所有 Long/Snowflake ID 在 JSON 与 TypeScript 中保持 string。

- 用户总数：全量配置用户数，包含停用用户。
- 闲置角色：没有任何用户配置关联的角色；停用用户的关联仍算占用，不能根据当前页用户推导。
- 无角色用户：未配置任何角色 ID 的用户。
- 授权关系数：全量用户与去重后的配置角色 ID 关联数。
- 未授权菜单：启用且运行可用的 MENU/LINK/BUTTON，在所有活动角色身份下均不可见的节点；不包含结构祖先、不可用插件或停用能力的菜单。

统计在仓储端聚合全量数据；用户分页/搜索结果只影响当前展开的用户节点。星图须标注用户分页与卫星展示上限，隐藏节点不代表无权限，配置关系线不代表用户此刻正在使用该角色。

## 编辑与验证

星图节点先展开详情，详情保留原有角色、用户和菜单编辑按钮；矩阵角色标题保留原权限树入口。原编辑入口须有相应 edit 权限，跨页用户/菜单编辑还须有其 view 权限。权限节点可查看登记说明、动作分类、显式/通配角色来源和直接菜单绑定；用户数量只反映当前载入页的配置关系。

矩阵默认只读，`system:role:edit` 可开启编辑、逐格勾选或调整当前筛选范围内的单个角色。筛选、分页和视图切换保留草稿；保存前列出授予、撤销和危险权限。全选只涉及明确显示的活动目录范围，原有未知或不可用权限保留。保存逐角色提交，部分失败单独报告，成功角色清除草稿，冲突角色保留意图供复核；不声称跨角色原子事务。离开页面须明确丢弃未保存草稿，保存过程中禁止离开或同时使用旧编辑流程。

快捷授予/撤销要求 `system:role:edit`，只修改一个活动登记权限；角色停用时修改的是配置，不会自动启用角色。用户角色分配要求 `system:user:assign-role`，读取用户详情另需 `system:user:view`；只可新增用户已有部门内的活动角色，原历史角色须明确取消才撤销，不自动切换用户会话。

增量接口：

- `PUT /api/system/roles/{id}/permission-changes`：`expectedPermissions` 为读取时的完整有序数组，`grant`/`revoke` 为本次差量。
- `PUT /api/system/users/{id}/role-changes`：`expectedRoleIds` 为读取时的完整有序数组，`grant`/`revoke` 为本次角色差量。

后端以原数组进行 CAS，冲突拒绝覆盖，并只更新权限/角色字段；版本号同步递增，使旧流程已读取对象的并发 save 受仓储版本校验。原全量编辑 API 保留既有语义，界面将两种编辑流程互斥，并在增量保存后立即更新角色列表和全景、使旧查询失效，避免使用旧列表快照重新覆盖。用户授权 CAS 同时验证本次新增角色所属部门仍在用户部门内。界面不得在冲突后偷偷重读并自动重试覆盖。

保存、启停、导入或从用户/菜单编辑返回后刷新全景。异步查询须防止过期响应覆盖新选择，查询失败必须可重试。星图使用页面级 SVG 表达截图的球体、刻度环和轨道，新增按钮/输入/详情复用既有 Yd 入口；不修改共享图谱组件，不增加外部图数据库依赖。

变更至少验证：权限树搜索下保留隐藏/未知选择、assign-* 分类、系统与历史通配锁定、停用角色的配置语义、用户/菜单读取隔离、全量统计不受分页影响、他人会话隔离、真实菜单可见规则，以及增量 CAS、部门并发变更、矩阵草稿冲突和部分成功。执行受影响后端定向测试、前端测试 typecheck、完整 Vue typecheck/构建及定向 lint。

## 权限目录生成与重建

同码登记只生成一个目录叶子。名称从实际声明中按动作语义、出现次数、长度及字典序稳定选择；说明合并同码端点的真实用途，禁止依靠 HashSet 或扫描顺序选择元数据。来源优先级为 **已装配端点 ANNOTATION → 实际注册插件/工具 MANUAL → 菜单叶子 MENU**，菜单不能覆盖端点和插件登记。

CATEGORY/LAYOUT 是结构节点，不独立生成权限；MENU/LINK/BUTTON 的真实入口或动作权限仍须登记。历史页面入口码与 `:view` 接口码是不同检查，不能因为显示同组就合并、重命名或撤销角色中的原码。MENU 元数据明确标注入口/按钮用途，并合并引用同码的菜单说明。

目录重建仅清空 `sysPermission` 的记录并从当前已装配端点、运行时注册资产和现存菜单叶子生成；保留集合索引。先保存可回读的 EJSON 备份与 SHA256、角色权限和用户角色/部门配置指纹，验证完整计划后再写入。写入失败立即恢复备份。重建不得重新播种菜单、修改用户/角色授权或触发插件重新启停。停用插件的旧码可作为不可用兼容目录保留，不能无依据恢复 ACTIVE。执行后验证权限码唯一、来源优先级、资源分组，以及授权配置和菜单指纹未变化；数据库备份与审计报告放本地 `config/backup`，不提交仓库。
