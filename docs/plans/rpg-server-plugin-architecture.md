# RPG服务器插件架构规划

> 基于 MMORPG服务器项目手册 H1.9 与 YuDream Admin 2.x 架构
> 
> 规划日期：2026-10-14
> 文档性质：架构方案草案

## 目标

为胡杨方块社 × 星空社联合 MMORPG 服务器提供完整的管理后台与玩家服务平台，基于 YuDream Admin 插件化架构实现。

---

## 一、架构分层

```
┌─────────────────────────────────────────────────────────┐
│              玩家前台（Vue3 + TypeScript）                │
│   官网、社区、角色查询、装备模拟器、赛季排行榜           │
└─────────────────────────────────────────────────────────┘
                            ↕ REST API
┌─────────────────────────────────────────────────────────┐
│           YuDream Admin 宿主（Spring Boot）              │
│   用户认证、权限管理、插件加载、菜单聚合、主题系统        │
└─────────────────────────────────────────────────────────┘
                            ↕ Plugin SPI
┌─────────────────────────────────────────────────────────┐
│                    RPG 业务插件矩阵                       │
│  复用插件 | 新开发插件 | 游戏服桥接插件                  │
└─────────────────────────────────────────────────────────┘
                            ↕ MySQL / Redis / RCON
┌─────────────────────────────────────────────────────────┐
│              Folia 游戏服（多世界实例）                   │
│   MythicMobs, MMOCore, DungeonsXL, SlimeWorldManager   │
└─────────────────────────────────────────────────────────┘
```

### 2.3 新开发的RPG核心插件

#### **A. 游戏数据桥接层**

##### `rpg-game-bridge`（游戏服数据同步）

**职责**：
- 连接 Folia 服务器（RCON + MySQL 共享）
- 同步玩家角色数据（等级、学科、装备评分）
- 实时在线状态、副本进度
- 经济流水记录（金币、学分）

**技术实现**：
- RCON 协议执行指令查询
- 共享 MySQL 数据库（MMOCore 玩家表）
- Redis 缓存热数据

**SPI 集成**：
- 提供 `GamePlayerService` 供其他插件调用
- 发布 `PlayerLevelUpEvent` 等游戏事件

---

##### `rpg-dungeon-manager`（副本管理）

**职责**：
- 副本配置管理（试炼窟、远征、极限挑战）
- 副本开放时间表（赛季节奏）
- 首杀记录、通关统计
- 掉落配置与概率调整

**管理后台功能**：
- 副本列表（类型、难度、人数、奖励）
- 通关记录查询（队伍、用时、评分）
- 数值调整界面（怪物血量、掉落率）
- 世界首领日程配置

**玩家前台功能**：
- 副本图鉴（解锁条件、Boss 介绍）
- 个人通关记录
- 服务器首杀榜

**技术要点**：
- 对接 DungeonsXL 数据库
- MythicMobs Boss 配置热重载接口

---

##### `rpg-economy-monitor`（经济监控）

**职责**：
- 金币、学分产出与回收统计（按 2.9 经济平衡表）
- 资源区枯竭状态监控
- 大额交易告警（表8 监控层）
- 经济周报生成

**管理后台**：
- 实时经济仪表盘（产出/回收曲线）
- 玩家财富排行
- 异常交易审计日志
- 资源区台账（剩余量、枯竭预警）

**技术实现**：
- 定时任务拉取 MMOItems 交易日志
- Elasticsearch 存储经济流水（可选）
- Grafana 可视化（或自研图表）

---

#### **B. 赛季运营支撑**

##### `rpg-season-manager`（赛季管理）

**职责**：
- 赛季生命周期管理（筹备→运营→收尾）
- 等级上限配置（每资料片提升）
- 赛季末重置流程（装备进度清空、外观保留）
- 学园祭典活动配置

**管理后台**：
- 赛季时间轴配置
- 版本内容清单（新副本、新学科）
- 赛季结算工具（奖励发放、数据归档）
- 活动日历（表14）

**技术要点**：
- 定时任务触发赛季切换
- 数据归档脚本（调用游戏服备份）
- 公告自动发布（对接 cms/news）

---

##### `rpg-volunteer-ops`（志愿者运营工作台）

**职责**：
- Bug 工单系统（表13 分级响应）
- 值班排班表
- GM 操作日志（表8 审计层）
- 玩家申诉处理

**权限分级**：
- 技术负责人：全部权限
- 数值管理员：经济、副本配置
- 内容负责人：任务、文案审核
- 客服：查看玩家数据、处理申诉

**技术实现**：
- 工单状态机（待响应→处理中→已解决）
- Webhook 通知（钉钉/飞书/QQ频道）
- 操作日志强审计（不可删改）

---

#### **C. 玩家服务前台**

##### `rpg-player-portal`（玩家个人中心）

**职责**：
- 角色信息展示（学科、等级、装备评分）
- 成就与收藏（外观纹饰、称号、坐骑）
- 社团信息（公会名、等级、据点截图）
- 个人统计（副本次数、PvP 战绩）

**前台页面**：
- `/player/{username}` 角色详情
- `/player/{username}/achievements` 成就墙
- `/player/{username}/equipment` 当前配装
- `/player/{username}/social` 好友与社团

---

##### `rpg-ranking`（排行榜）

**职责**：
- 实时排行（等级、装备评分、PvP 段位）
- 副本通关榜（首杀、速通）
- 社团排行（社团等级、活跃度）
- 生活职业榜（各学科熟练度）

**前台展示**：
- 分页表格 + 实时刷新
- 筛选条件（按学科、按服务器）
- 历史赛季归档榜单

**技术实现**：
- Redis Sorted Set 存储实时榜
- 定时任务从游戏服同步
- 前端 SSE 推送榜单变化

---

##### `rpg-wiki-integration`（游戏百科）

**职责**：
- 扩展 `wiki` 插件，添加游戏专属条目类型
- 学科图鉴（技能树、装备需求）
- 怪物图鉴（掉落、弱点）
- 副本攻略模板（机制时间轴、站位图）

**内容结构**：
```
/wiki/subjects/{subjectId}  # 学科详情
/wiki/dungeons/{dungeonId}  # 副本攻略
/wiki/monsters/{monsterId}  # 怪物图鉴
/wiki/items/{itemId}        # 物品数据库
```

**编辑权限**：
- 内容负责人可编辑
- 玩家可提交草稿（审核后发布）

---

#### **D. 数据分析与决策**

##### `rpg-analytics`（数据分析）

**职责**：
- 赛季运营周报生成（表15 指标）
- 玩家留存漏斗（白名单→首周→第4周）
- 副本参与率热力图
- 跨校组队占比分析

**管理后台**：
- 自定义报表配置
- 数据导出（CSV/Excel）
- 图表库（ECharts）

**技术实现**：
- ClickHouse 存储明细数据（可选）
- 定时 ETL 任务聚合
- 对接宿主 `platform:ai` 生成洞察报告

## 三、技术选型与约束

### 3.1 后端技术栈

| 技术 | 版本 | 用途 |
|-----|------|-----|
| Spring Boot | 3.x | 宿主框架 |
| YuDream Plugin SPI | 2.35.0+ | 插件契约 |
| MySQL | 8.0+ | 主数据库（与游戏服共享） |
| Redis | 7.x | 缓存与实时榜单 |
| RCON Client | 自研/开源 | 游戏服指令通道 |

### 3.2 前端技术栈

| 技术 | 版本 | 用途 |
|-----|------|-----|
| Vue 3 | 3.x | 宿主前端 |
| @yudream/components | 最新 | YD 组件库 |
| @yudream/plugin-sdk | 1.6.0+ | 插件前端 SDK |
| ECharts | 5.x | 数据图表 |
| Sigma.js | 2.x | 社团关系图谱 |

### 3.3 游戏服集成约束

**共享数据库表**：
- `mmocore_playerdata`（玩家学科数据）
- `mmoitems_inventory`（装备与物品）
- `dungeonsxl_instance`（副本实例）
- `luckperms_*`（权限同步，如需）

**RCON 指令接口**：
```bash
# 查询玩家在线
list

# 获取玩家数据
mmo info <player>

# 执行GM操作（需游戏服插件支持）
rpg give <player> <item> <amount>
```

**性能约束**：
- RCON 调用频率：≤10次/秒
- 数据库查询缓存：热数据 TTL 60s
- 避免高峰期（19:00-23:00）执行重查询

## 四、开发工作流

### 4.1 插件开发顺序

**阶段 0（技术验证，2周）**：
1. `rpg-game-bridge` 基础版（RCON + MySQL 连通性）
2. 在本地搭建 Folia + MMOCore 测试环境
3. 验证数据同步可行性

**阶段 1（核心功能，4周）**：
1. `rpg-player-portal` 角色查询页面
2. `rpg-dungeon-manager` 副本配置后台
3. `rpg-season-manager` 赛季时间轴

**阶段 2（运营支撑，3周）**：
1. `rpg-economy-monitor` 经济仪表盘
2. `rpg-volunteer-ops` 工单系统
3. `rpg-ranking` 排行榜前台

**阶段 3（体验优化，2周）**：
1. `rpg-wiki-integration` 游戏百科
2. `rpg-analytics` 数据周报
3. 全链路压测与性能优化

### 4.2 双仓协作流程

```
yudream-admim（主仓）
├── 宿主核心改动（如需）
├── rpg-game-bridge（桥接层插件）
└── rpg-volunteer-ops（管理后台）

yudream-admin-plugins（插件仓）
├── rpg-player-portal（玩家前台）
├── rpg-dungeon-manager
├── rpg-season-manager
├── rpg-economy-monitor
├── rpg-ranking
├── rpg-wiki-integration
└── rpg-analytics
```

**同步规则**：
- 契约变更（SPI）：主仓先行，插件仓跟进
- 前端组件：YD 组件需求提到主仓，插件仓复用
- 发布节奏：插件仓按 RPG 赛季节奏独立发版

### 4.3 测试策略

**单元测试**：
- 覆盖率 ≥70%（DDD 领域层必测）
- Mock 游戏服数据（不依赖真实 Folia）

**集成测试**：
- Docker Compose 启动 MySQL + Redis + Mock游戏服
- 测试数据同步链路

**压力测试**：
- 模拟 150 CCU 并发查询
- RCON 调用频率测试
- 排行榜刷新性能

## 五、部署架构

### 5.1 生产环境拓扑

```
                          ┌─────────────┐
                          │   Nginx     │
                          │  (SSL + 反向代理) │
                          └──────┬──────┘
                                 │
                ┌────────────────┼────────────────┐
                │                │                │
         ┌──────▼──────┐  ┌──────▼──────┐  ┌──────▼──────┐
         │  YDA 宿主    │  │  静态资源    │  │  CDN (资源包) │
         │  (8080)     │  │  (前端)      │  │              │
         └──────┬──────┘  └─────────────┘  └──────────────┘
                │
    ┌───────────┼───────────┐
    │           │           │
┌───▼───┐  ┌───▼───┐  ┌───▼───┐
│ MySQL │  │ Redis │  │ Folia │
│ (共享) │  │ (缓存) │  │ (RCON)│
└───────┘  └───────┘  └───────┘
```

### 5.2 备份策略

遵循手册表7三层备份：
- **热备**：YDA 每日备份数据库
- **冷备（塔大）**：每周全量同步到对象存储
- **冷备（星空社）**：异地冗余

## 六、风险与应对

### 6.1 技术风险

| 风险 | 概率 | 影响 | 应对措施 |
|-----|------|------|---------|
| Folia 插件不兼容 | 中 | 高 | 阶段0验证，回退 Paper |
| RCON 性能瓶颈 | 中 | 中 | 增加 Redis 缓存层 |
| 数据库锁冲突 | 低 | 高 | 读写分离，只读副本 |
| 资源包分发慢 | 中 | 低 | CDN 加速，分片下载 |

### 6.2 运营风险

| 风险 | 概率 | 影响 | 应对措施 |
|-----|------|------|---------|
| 志愿者流失 | 高 | 中 | 文档完善，权限自动回收 |
| 双校协调不畅 | 中 | 中 | 周例会 + 共享知识库 |
| 玩家数据泄露 | 低 | 高 | 敏感数据加密，审计日志 |
| 经济系统崩盘 | 中 | 高 | 每周经济周报，异常告警 |
